Thanks — this is a great, solvable-sounding problem. I read your C# port and the extractor code you included. I found two likely causes for the extra ~12.3k Variable nodes in the .NET service (compared to Python) and some clear opportunities to speed up parsing:


Root cause (very likely): the C# extract_constants_variables implementation builds a Dictionary<string, DataDefinitionJSON> using the raw matched term as the key, but matches are discovered against an UPPERCASED line while the substring is taken from the original line. Because dictionary key checks are case-sensitive by default, the same variable with different case (e.g. VAR, Var, var) can be inserted multiple times as separate keys. Python’s extractor normalizes keys (so duplicates are collapsed) — your C# version does not. This will produce many duplicate Variable entries (and therefore many extra Neo4j Variable nodes). Evidence in your uploaded file: the C# extractor uses upper_line = line.ToUpper(); var var_matches = variable_regex.Matches(upper_line); ... variable_dict.ContainsKey(variable) and variable = line.Substring(match.Index, match.Length). oldresp oldresp


Secondary cause (performance): ConstantVariableExtractor is constructed per-parsed-file and re-reads the lexer grammar file + recompiles multiple regular expressions each time. Reading/parsing the grammar file and re-creating Regexes is expensive and will slow down the dotnet parser versus a Python implementation that either caches these or compiles regexes once. Evidence: ConstantVariableExtractor() calls read_keywords() in the constructor and creates many Regex objects as instance fields. oldresp


Below I give a robust fix that addresses both issues without changing other node creation logic, plus concrete step-by-step edits and test steps you can apply immediately.

Recommended changes (summary)


Make variable-key lookup case-insensitive (collapse duplicates): either use a Dictionary<string,DataDefinitionJSON>(StringComparer.OrdinalIgnoreCase) or normalize keys with ToUpperInvariant() (or ToLowerInvariant()) before using them as keys. This will remove the extra duplicate Variable nodes.


Cache / static-compile regexes and keywords so you do not read/parse the lexer grammar file or recompile regexes for every file. Use static readonly fields and RegexOptions.Compiled | RegexOptions.IgnoreCase where appropriate.


Minor: if you still want variable Term to preserve original case, store the original matched substring in the DataDefinitionJSON.Term while still using a normalized key in the dictionary.


Add a small diagnostic mode (one-off) to count duplicates and confirm the fix.


These changes preserve the shape of the DataDefinitionJSON objects and the downstream CreateVariableEntityList code — you are only deduplicating and speeding up extraction.

static ConstantVariableExtractor()
{
    // ensure keywords are loaded once
    try
    {
        // read keywords once
        var tempKeywords = new HashSet<string>(StringComparer.OrdinalIgnoreCase);

        // Find the TSqlLexer.g4 the same way you did (assembly relative)
        string currentDir = Path.GetDirectoryName(System.Reflection.Assembly.GetExecutingAssembly().Location);
        string targetFilePath = Path.Combine(currentDir, "..", "..", "..", "grammer", "TSqlLexer.g4");
        targetFilePath = Path.GetFullPath(targetFilePath);

        string startMarker = "// Keywords Start Here";
        string endMarker = "// Keywords End Here";
        bool capture = false;

        if (File.Exists(targetFilePath))
        {
            foreach (string line in File.ReadLines(targetFilePath))
            {
                string trimmedLine = line.Trim();
                if (trimmedLine == startMarker) { capture = true; continue; }
                if (trimmedLine == endMarker) { capture = false; break; }

                if (capture && !string.IsNullOrEmpty(trimmedLine) && !trimmedLine.StartsWith("//"))
                {
                    Match colonMatch = Regex.Match(trimmedLine, @":(.*?);");
                    if (colonMatch.Success)
                    {
                        string afterColon = colonMatch.Groups[1].Value;
                        MatchCollection keywordMatches = Regex.Matches(afterColon, @"'[^']*'");
                        foreach (Match keywordMatch in keywordMatches)
                        {
                            string keyword = keywordMatch.Value.Trim(" '".ToCharArray());
                            tempKeywords.Add(keyword);
                        }
                    }
                }
            }
        }

        foreach (var k in tempKeywords) keywords.Add(k);

        // Build negative lookahead
        negative_lookahead = string.Join("|", keywords.Select(k => Regex.Escape(k)));

        // Variable pattern and compiled regexes (Compiled for performance)
        variable_pattern = $@"(?<!@)(?!(?:{negative_lookahead})(?=[\s(]|$))\b[A-Z]+(?:[-._][A-Z0-9]+)*\b";
        variable_regex = new Regex(variable_pattern, RegexOptions.IgnoreCase | RegexOptions.Compiled);

        keywords_as_vars = new Regex($@"(?:(?<=\s)|(?<=^))(@[A-Z][A-Z0-9_]*)(?=[\s(]|$)", RegexOptions.IgnoreCase | RegexOptions.Compiled);

        string_constant_regex = new Regex(@"'([^']*)'", RegexOptions.Compiled);

        numeric_constant_regex = new Regex(@"(?<=\s)\d+(?=\s)|(?<=\s)\d+$", RegexOptions.Compiled);

        calc_regex = new Regex(
            $@"(?!(?:T|CT|ECT|LECT|ELECT|{negative_lookahead})(?=\s|$))" +
            $@"(?:(?:SET|SELECT)?\s*(@[\w]+)?\s*(?:=\s*)?)?\(*\s*@[\w.]+(?:\s*[+\-*/]\s*[@\w.()]+)+\s*\)*",
            RegexOptions.IgnoreCase | RegexOptions.Compiled
        );

        pattern_resultant = @"SET\s+(@\w+)\s+=";
    }
    catch
    {
        // swallow — keep defaults (non-fatal)
    }
}


Why: constructing these once and using RegexOptions.Compiled drastically reduces the per-file overhead of regex compilation and reading the grammar file.

var variable_details = new List<DataDefinitionJSON>();
// use case-insensitive keys to collapse VAR/Var/var duplicates
var variable_dict = new Dictionary<string, DataDefinitionJSON>(StringComparer.OrdinalIgnoreCase);

foreach (string line in lines)
{
    // Skip commented lines
    if (line.Trim().StartsWith("--"))
        continue;

    // Extract string constants
    MatchCollection string_matches = string_constant_regex.Matches(line);
    foreach (Match match in string_matches)
    {
        string constant = match.Groups[1].Value;
        string key = constant; // case-insensitive dict will normalize keys
        if (!variable_dict.ContainsKey(key) && constant.Trim('\'').Split(' ').Length == 1)
        {
            // store the original case in the DataDefinitionJSON.Term if you want to preserve it
            variable_dict[key] = new DataDefinitionJSON(
                type: "CONSTANT",
                term: constant,
                usage_context: new List<string> { line },
                file_path: file_path,
                meaning: ""
            );
        }
        else if (variable_dict.ContainsKey(key))
        {
            variable_dict[key].usage_context.Add(line);
        }
    }

    // Extract variables (uppercase identifiers) — note: variable_regex is compiled and case-insensitive
    MatchCollection var_matches = variable_regex.Matches(line);
    var variables = new List<string>();
    foreach (Match match in var_matches)
    {
        // use the matched value exactly (preserves case), but dictionary is case-insensitive
        string variable = match.Value;
        variables.Add(variable);
    }

    foreach (string variable in variables)
    {
        string key = variable;
        if (!variable_dict.ContainsKey(key) && variable.Trim('\'').Split(' ').Length == 1)
        {
            variable_dict[key] = new DataDefinitionJSON(
                type: "DECLARATION",
                term: variable,
                usage_context: new List<string> { line },
                file_path: file_path,
                meaning: ""
            );
        }
        else if (variable_dict.ContainsKey(key))
        {
            variable_dict[key].usage_context.Add(line);
        }
    }

    // Extract keyword variables (@VAR_NAME)
    MatchCollection keyword_var_matches = keywords_as_vars.Matches(line);
    var keyword_vars = new List<string>();
    foreach (Match match in keyword_var_matches)
    {
        keyword_vars.Add(match.Value);
    }

    foreach (string key_var in keyword_vars)
    {
        string key = key_var;
        if (!variable_dict.ContainsKey(key) && key_var.Trim('\'').Split(' ').Length == 1)
        {
            variable_dict[key] = new DataDefinitionJSON(
                type: "DECLARATION",
                term: key_var,
                usage_context: new List<string> { line },
                file_path: file_path,
                meaning: ""
            );
        }
        else if (variable_dict.ContainsKey(key))
        {
            variable_dict[key].usage_context.Add(line);
        }
    }
}


Why: using StringComparer.OrdinalIgnoreCase will collapse identical logical variables differing only by case. If you prefer to normalize keys explicitly, you can use key = variable.ToUpperInvariant() (and keep dict comparer default); either is fine as long as consistent.

3) (Optional) Change how you capture var_matches (current code uppercases line)
You currently do upper_line = line.ToUpper(); var var_matches = variable_regex.Matches(upper_line); and then line.Substring(match.Index, match.Length) to get the original. That can be brittle (index differences if different encoding/newlines). Remove the ToUpper() step and run regex directly on line because your regex is already IgnoreCase/compiled. So replace:
string upper_line = line.ToUpper();

{
    variables.Add(line.Substring(match.Index, match.Length));
}

with:
MatchCollection var_matches = variable_regex.Matches(line);
foreach (Match match in var_matches)
{
    variables.Add(match.Value);
}


Why: this avoids potential index/culture differences and keeps behavior consistent.


Performance / caching tweaks (summary)


Make the ConstantVariableExtractor heavy objects (keyword list and compiled regexes) static as shown. This will stop reading TSqlLexer.g4 and recompiling regexes per file.


Add RegexOptions.Compiled where regexes are used often (careful on startup time but good for long runs).


If your application runs multi-threaded, the static initialization above is thread-safe because the CLR runs static constructors once.

Why these changes are safe

The rest of the pipeline still consumes DataDefinitionJSON and VariableEntity in the same shapes, so Neo4j node creation logic & other node types remain untouched.
